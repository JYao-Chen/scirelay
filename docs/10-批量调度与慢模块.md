# 10. 批量调度与慢模块

SDK 的 `ScienceClient.run_batch` 在一个任务队列中推进所有论文的模块，不逐篇等待。`ScienceClient.run` 也使用同一调度器；领域抽取继续使用独立的 `DomainExtractor`，不混入通用模块结果。

## 10.1 并发与超时

- `workers` 限制执行线程；`max_concurrency` 限制同一客户端实例正在进行的 HTTP 请求数，两者取较小值。不同进程或客户端实例不共享额度。
- `module_limits` 限制指定模块的并发，所有模块默认同等处理，无特殊模块。每模块公平份额为总有效并发除以选定模块数后向上取整（至少1），显式模块上限与公平份额取较小值。调度器跳过没有空闲额度的模块，避免等待任务占满线程。
- 不同论文可同时推进；模块间轮转派发，组内按文档清单顺序推进。不保证所有工作负载都能用满总并发，优先保障不同模块之间的隔离。
- `timeout` 默认600秒，可用 `module_timeouts` 覆盖各模块。它是 HTTP 读取等待，不是总任务期限，也不能解除服务器内部超时。
- 请求失败不会在一次运行内自动重试。显式续跑才再次提交未成功模块，避免不透明地重复提交可能仍在远端计算的请求。

## 10.2 自动识别疑似阻塞

任意模块满足下列条件之一，即在当前调度中标记为 blocked：尚未返回的尝试超过 `slow_after`（默认120秒），或连续失败达到 `failure_threshold`（默认2次）。这些是客户端观察信号，不证明远端死锁；长文正常耗时也可能触发，可按业务调整阈值。

默认 `blocked_action="throttle"` 将该模块的后续并发降至1，其他模块继续轮转；仍执行所有必需任务。`blocked_action="defer"` 则延后该模块所有尚未发出的任务，标记 `auto_deferred`，其他模块继续完成。此策略适合先获取可用结果，再单独补缺。

已发出的请求继续占用槽位，直到返回或 HTTP 超时；不会假装取消远端任务，也不会用脱离后台线程的方法虚报批次结束。只有一个有效并发槽时，必须等当前请求结束才能推进其他任务。自动延后不是自动改变字段的重要性：必需模块有缺项仍为 partial，明确设为 optional 的缺项才允许 complete_with_gaps。

逐篇和批次结果的 `scheduler` 记录阈值、策略及逐模块健康状态、连续失败数和触发原因。健康状态在每次显式续跑时重置，从而重新尝试缺项；成功缓存继续复用。当前运行一旦判定 blocked 即保持限制，不自动恢复为高并发。

无需提前知道哪个模块慢：

```bash
uv run --env-file .env scirelay batch documents.json --output runs/adaptive \
  --slow-after 120 --failure-threshold 2 --blocked-action defer

# 后续补跑；默认 throttle，避免再次自动延后，仍然保留阻塞隔离。
uv run --env-file .env scirelay batch documents.json --output runs/adaptive
```

## 10.3 可选与延后是两个独立策略

`modules` 定义本次运行需要收集的固定模块集合；默认全部五个。`optional_modules` 决定哪些模块缺失时仍允许必需工作完成；它本身不阻止网络请求。`deferred_modules` 才会跳过没有成功缓存的模块，已有成功缓存继续纳入。

建议将慢且当前非必需的 `related_work` 同时设为 optional 和 deferred。第一轮只处理其他四个模块；第二轮取消 deferred 即可补跑相关工作，成功缓存不重复请求。延后必需模块会得到 partial，不能通过延后操作掩盖必需缺项。

运行状态：

| 状态 | 含义 |
| --- | --- |
| complete | 所有选定模块均有成功结果 |
| complete_with_gaps | 必需模块完成，可选模块仍有缺项或失败 |
| partial | 必需模块缺失，或批次中存在输入/配置失败的论文 |
| running / processing | 处理中，不能作为最终完成状态 |

结果保存 `required_complete`、`all_modules_complete`、`missing_modules`、逐模块 `module_status`、`errors`、`attempts`。尝试记录含开始/结束时间、超时配置和已脱敏错误。complete 仅描述执行完整性，不证明科学事实正确。

## 10.4 命令行

创建清单 `documents.json`，值为适配后的文档目录，内含 `article.json` 和 `full.md`。路径相对于清单文件；也可使用绝对路径。

```json
{"paper-a": "prepared/paper-a", "paper-b": "prepared/paper-b"}
```

论文 ID 只允许英文字母、数字、下划线、连字符、内部空格和点，禁止路径穿越；同一批次不能更换清单。每个运行目录只允许一个写入进程。

第一轮跳过相关工作：

```bash
uv run --env-file .env scirelay batch documents.json --output runs/batch \
  --workers 10 --max-concurrency 10 --module-limit related_work=1 \
  --module-timeout research_idea=900 --module-timeout related_work=600 \
  --optional-modules related_work --defer-modules related_work
```

原目录补齐缺项，默认将所有模块作为必需模块：

```bash
uv run --env-file .env scirelay batch documents.json --output runs/batch \
  --workers 10 --module-limit related_work=1 --module-timeout related_work=900
```

只读状态，无需密钥，不访问接口：

```bash
uv run scirelay status runs/batch
```

`extract` 单篇命令也支持全部调度策略参数。CLI 在 complete 或 complete_with_gaps 时返回0；partial/failed/running/processing 返回1。调用方若要求结果齐全，应检查 `all_modules_complete`。

## 10.5 Python 调用

```python
from scirelay import ModelConfig, ScienceClient

client = ScienceClient(
    ModelConfig.from_env(), max_concurrency=10,
    module_limits={"related_work": 1},
    module_timeouts={"related_work": 600, "research_idea": 900},
)
documents = {"paper-a": "/data/prepared/paper-a", "paper-b": "/data/prepared/paper-b"}
first = client.run_batch(
    documents, "runs/batch", workers=10,
    optional_modules=["related_work"], deferred_modules=["related_work"],
)
# 在后续批次窗口显式补跑；其他四个模块继续复用成功缓存。
second = client.run_batch(documents, "runs/batch", workers=10)
```

完整示例见 `examples/batch.py`。`examples/pipeline.py` 先 OCR/适配，再调用跨论文通用队列，最后运行可选领域抽取；支持 `--blocked-action defer` 自动延后疑似阻塞模块，也可用 `--defer-modules` 显式延后指定模块。后续以默认 throttle 重跑即可补缺。

## 10.6 续跑、恢复与边界

批次在 `summary.json` 逐任务更新；逐篇在 `papers/<paper-id>/` 保存 `run.json`、`extraction_result.json`、`stages/<module>.json`。一个失败论文不会阻止其他论文执行。输入、服务、模型、模块集合发生改变必须新建运行目录；可选/延后策略、并发和超时可以在原目录调整。

没有成功缓存的任务可在显式续跑时重提。缓存损坏会记录失败，不会自动覆盖或发起付费请求；检查后移走损坏的阶段文件，再显式续跑。不要在写入进程运行时修改缓存。

不具备跨进程锁、远端取消、服务端后台任务查询、自动定时补跑或永驻守护服务。进程退出后可以从落盘的成功阶段恢复；HTTP 超时或进程终止不能证明远端计算已经停止。任务开始时间是调度尝试的开始，可能包含等待共享额度的时间。
